# Phase 1 foundations

## Analytics

The marketplace has one GA4 configuration source: `config/analytics.php`, populated by `GA_ID` (or `GA4_MEASUREMENT_ID`) and disabled unless `ANALYTICS_ENABLED=true`. The public Blade shell disables GA automatic page views and emits one initial page view plus one event for each successful Inertia navigation. Consent Mode defaults to denied and is updated from `wow_cookie_preferences`.

The only sales event is `purchase`. It is emitted from the paid checkout success response after the database claim on `orders.analytics_purchase_emitted_at` succeeds. The transaction ID is `WOW-{order id}`; value/currency come from the persisted order and items include stable catalogue/provider/offering/product identifiers where present. The client session guard is a second safety net for remounts. Stripe webhook retries reconcile the order but never emit browser analytics.

`view_item`, `select_item`, `begin_checkout`, `add_payment_info`, and `add_to_cart` are reserved for their real user actions. Legacy `wow_v3_*` names are normalised to the GA4 name once; they are not sent as an additional conversion. Search telemetry persists first-touch/session UTMs, records structured context, and emits one `no_results` after a confirmed empty response. `availability_fallback` is available to search surfaces when a local request is fulfilled by an online/other fallback.

## Sitemap architecture

`/sitemap.xml` is the only canonical index. It is generated by `SitemapService` into bounded child files (`static`, `schedules`, `types`, `modalities`, `near-me`, `offerings`, `locations`, `online`, `by-need`, `practitioners`, and `guides`). Eligibility comes from public/live records and real location/online relationships; utility URLs, redirects, empty slugs, null segments, queries and fragments are rejected before XML. `search`, cart, checkout, account, admin and dashboard paths are never eligible.

Generation uses atomic replacement and retains the previous valid artefact until all new files have been written. It no longer boots the HTTP kernel for every candidate URL (the former timeout/N+1 source). Run `php artisan sitemaps:validate` before Search Console submission. The validator parses the index and every child, detects malformed/null/duplicate/utility URLs, and (unless `--skip-http` is supplied) checks 2xx responses, redirects, noindex and canonical mismatches. The scheduler generates at midnight, validates at 00:10, and submits the canonical index at 00:20.

## Reconciliation and limitations

WOW order rows remain the authoritative internal sales dataset. GA4 export files are surfaced by the existing Studio analytics service; a future credentialed GA Data API job can compare `WOW-{order id}` transaction IDs, counts, values, currencies, refunds and attribution. No fake external API integration is used. External Search Console/GA attribution gaps (consent-denied sessions, gateway-side modelling and property configuration) must still be monitored in the admin reports.
